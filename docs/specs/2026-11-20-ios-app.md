# iOS app — wrapper + share extension

**Status:** proposed 2026-11-20 · **Target:** App Store launch Friday 26 Feb 2027
**Why:** iPhone Safari and installed web apps cannot receive a shared screenshot or link from Instagram/TikTok (the Web Share Target in `public/manifest.json` + `public/sw.js` only works on Android). A real app with a native share extension is the only way to get "share to Curated" on iPhone.

## Approach (recommended): Capacitor wrapper around the existing React app

Bundle the built `dist/` into a native iOS shell and add a Share Extension. Reuses ~all of `src/App.jsx`; the native work is small and well-bounded.

- **Not** `server.url` pointing at the live site: Apple rejects thin website wrappers (guideline 4.2). Ship the bundled build.
- **Alternative considered:** rebuild in FlutterFlow (`docs/flutterflow-brief.md`). Slower, throws away a working app, and 14 weeks is not enough margin. Rejected unless the wrapper hits a wall.
- Needs: Mac with Xcode (have), Apple Developer Program (£79, enrol first — approval can take a couple of days).

## Work items

### 1. Wrapper spike (do first — de-risks everything)
- Add Capacitor, generate the iOS project, run the bundled app in the simulator and on a real phone.
- Exit test: login, Discover, save a spot, generate a plan all work.

### 2. API base URL
- App.jsx makes ~32 relative `fetch("/api/...")` calls. Inside the app the origin is `capacitor://localhost`, so they must go to `https://london-app.vercel.app`.
- Add one `API_BASE` constant (empty on web, full URL in native build) and use it everywhere.
- `applyCors` in `api/_auth.mjs` must allow `capacitor://localhost` (it currently allows only `ALLOWED_ORIGINS` and `london-app-*.vercel.app`). Keep the allow-list explicit.

### 3. Sign-in
- **Google OAuth is blocked in embedded web views** (`disallowed_useragent`). Use the system browser or a native Google sign-in plugin, returning through a custom URL scheme / universal link. `signInWithGoogle` currently builds `redirectTo` from `window.location.origin`, which will not work natively.
- **Sign in with Apple is required** (App Store guideline 4.8) because the app offers Google login. Add it via Supabase Apple provider.
- Email one-time code already works unchanged.

### 4. Share extension (the headline feature)
- Native Swift Share Extension target that accepts images and URLs, writes them to a shared App Group container, and opens Curated.
- Evaluate an existing Capacitor share-extension plugin first; fall back to a small custom extension.
- App side: on launch/resume, read the shared item and feed it into the same code path the web share handler uses (`useEffect` near App.jsx:3863, which calls `handleParse([file], "screenshot")` or `prefillLink(text)`). Only the source of the file changes, from the service-worker cache to the App Group.
- Exit test: screenshot a TikTok in Instagram, tap Share, choose Curated, spot appears in the capture sheet parsed.

### 5. Native details
- `sw.js` registration is already guarded by `'serviceWorker' in navigator`; it does nothing in the wrapper. Leave it for the web version.
- `haptic()` (App.jsx:2754) uses `navigator.vibrate`, which iOS ignores. Swap in the Capacitor Haptics plugin.
- Safe-area insets, status bar style, splash screen, app icon set (1024 px master).
- Leaflet map and Google photo URLs: check they load from the bundled origin.

### 6. Store requirements
- **Account deletion in-app** is mandatory (5.1.1(v)). Already shipped (Me → delete account via `api/gdpr`). Verify it works from the native build.
- **Privacy:** privacy policy URL, App Privacy "nutrition label". Mixpanel is consent-gated and sends no email or device ad ID, so no App Tracking Transparency prompt should be needed. Confirm when filling the label.
- App Store listing: name, subtitle, description, keywords, screenshots (6.9" and 6.5" iPhone), support URL, age rating.
- Review notes: provide a demo login for the reviewer and explain how to trigger the share extension.

### 7. Beta via TestFlight
- Replaces the web beta for iPhone users. Internal testers (up to 100) need no review; external testers (up to 10,000, via public link) need a short beta review.
- Keep the web app live for Android and desktop users.

### Later (not launch-blocking)

## Risks
- **Share extension is the unknown.** Prove it in the spike week, not in January.
- **Review rejection** (sign-in, privacy label, minimal functionality). The buffer week exists for this.
- **Sign-in rework** touches the auth flow every user hits, so test on a fresh account and a returning one.
